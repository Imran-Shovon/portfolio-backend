# Deploying the portfolio stack

## Current production setup

| Piece | Where | URL |
|---|---|---|
| Portfolio website | Vercel project `portfolio` | https://portfolio-five-iota-cwznbgwsf2.vercel.app |
| Admin dashboard | Vercel project `portfolio-admin` | https://shovon-portfolio-admin.vercel.app |
| Content API (this repo) | Vercel project `portfolio-api` (serverless, `api/index.js` + `vercel.json`) | https://shovon-portfolio-api.vercel.app |
| Database | MongoDB Atlas, project `portfolio`, free M0 cluster `portfolio-db` (AWS Singapore) | — |
| Uploads | Vercel Blob store `portfolio-uploads` (public, Singapore), `STORAGE_DRIVER=vercel-blob` | — |

All three Vercel projects are connected to their GitHub repos and deploy `main` automatically.
Preview deployments stay behind Vercel Authentication; only the domains above are public.

API env vars (Vercel → portfolio-api): `MONGODB_URI`, `JWT_SECRET`, `NODE_ENV=production`, `TRUST_PROXY=1`,
`STORAGE_DRIVER=vercel-blob`, `BLOB_READ_WRITE_TOKEN` (added by the Blob store), `ADMIN_ORIGIN`.
Dashboard: `BACKEND_URL`. Portfolio: `CONTENT_API_URL`, `SITE_SLUG`, `REVALIDATE_SECRET`.

Limits on Vercel: uploads are capped at 4 MB (Vercel's 4.5 MB request limit), and rate limits are
counted per serverless instance. The public endpoint sends `Cache-Control: no-store`, so Vercel's
CDN never serves the website stale content after a save.

## Alternative: Render + Cloudinary

The steps below deploy the API on Render with Cloudinary uploads instead (`render.yaml`).

| Piece | Host | Repo |
|---|---|---|
| Content API (this repo) | Render (web service, free plan) | `Imran-Shovon/portfolio-backend` |
| Database | MongoDB Atlas (free M0) | — |
| Uploaded images and resumes | Cloudinary (free) | — |
| Admin dashboard | Vercel | `Imran-Shovon/portfolio-admin-dashboard` |
| Portfolio website | Vercel (already deployed) | `Imran-Shovon/portfolio` |

Do the steps in order: each one produces a value the next one needs. Collect them as you go:

```
ATLAS_URI          = mongodb+srv://...           (step 1)
CLOUDINARY_URL     = cloudinary://...            (step 2)
PORTFOLIO_URL      = https://<your-portfolio>.vercel.app   (already exists)
REVALIDATE_SECRET  = (printed by the seed)       (step 3)
API_URL            = https://<service>.onrender.com        (step 4)
ADMIN_URL          = https://<dashboard>.vercel.app        (step 5)
```

All commands below are PowerShell, run from the `portfolio-backend` folder.

---

## 1. MongoDB Atlas

1. Create a free account at https://cloud.mongodb.com and a **free M0 cluster**. Pick **AWS / Singapore (ap-southeast-1)**, the same region as the Render service.
2. **Database Access** → add a database user with a generated password (role: *Read and write to any database*).
3. **Network Access** → add `0.0.0.0/0`. Render's free plan has no fixed outgoing IP, so the user/password is the protection here. Use a long generated password.
4. **Connect → Drivers** → copy the connection string, insert the password, and add the database name before the `?`:
   `mongodb+srv://<user>:<password>@<cluster>.mongodb.net/portfolio?retryWrites=true&w=majority`

   This is your `ATLAS_URI`.

## 2. Cloudinary

1. Create a free account at https://cloudinary.com.
2. Dashboard → **API Keys** (or the Getting Started page) → copy the **API environment variable**: `cloudinary://<api_key>:<api_secret>@<cloud_name>`. This is your `CLOUDINARY_URL`.

Images are stored as image resources and PDFs as raw resources under the `portfolio/<siteId>/` folder.

## 3. Seed the production database (from your machine)

This creates the `shovon` site with the current portfolio content and your admin login, directly in Atlas. Use the **real portfolio URL**, since it becomes the site's URL, its allowed contact-form origin and its revalidate URL.

```powershell
$env:MONGODB_URI = "<ATLAS_URI>"
$env:SEED_SITE_URL = "<PORTFOLIO_URL>"
npm run seed
```

Copy the printed `REVALIDATE_SECRET`; it's only shown once (you can rotate it later in the dashboard → Site settings).

```powershell
$env:ADMIN_EMAIL = "you@example.com"
$env:ADMIN_PASSWORD = "<a long password, 10+ characters>"
npm run create-admin
```

Then close the terminal (or `Remove-Item Env:MONGODB_URI, Env:ADMIN_PASSWORD`) so the production credentials don't linger.

## 4. Backend on Render

1. https://dashboard.render.com → **New → Blueprint** → connect GitHub → pick `portfolio-backend`. Render reads `render.yaml`.
2. It asks for the values marked `sync: false`:

   | Variable | Value |
   |---|---|
   | `MONGODB_URI` | `ATLAS_URI` |
   | `CLOUDINARY_URL` | `CLOUDINARY_URL` |
   | `ADMIN_ORIGIN` | `ADMIN_URL`. Not known yet, so enter `https://placeholder.vercel.app` and fix it after step 5 |

   `JWT_SECRET` is generated by Render, and `PUBLIC_BASE_URL` comes from Render's own URL automatically.
3. **Apply**. The first build takes a few minutes. When it's live, note the service URL (`API_URL`) and check:
   - `<API_URL>/health` → `{"status":"ok"}`
   - `<API_URL>/api/v1/public/sites/shovon` → the content JSON

The free plan sleeps after 15 minutes without traffic, and the next request takes ~30–60s. The website itself stays fast because Vercel serves cached pages, but the first contact-form submission or dashboard login after a quiet period will be slow. To avoid it, upgrade the service to **Starter** ($7/month), or point a free uptime pinger (e.g. https://cron-job.org) at `<API_URL>/health` every 10 minutes.

## 5. Admin dashboard on Vercel

1. https://vercel.com/new → import `portfolio-admin-dashboard` (framework: Next.js, defaults are fine).
2. **Environment Variables** (Production and Preview):

   | Variable | Value |
   |---|---|
   | `BACKEND_URL` | `API_URL` (no trailing slash, no `/api/v1`) |

3. **Deploy**, then note the URL (`ADMIN_URL`).
4. Back in Render → `portfolio-api` → **Environment** → set `ADMIN_ORIGIN` = `ADMIN_URL` → save (it redeploys).

The dashboard calls the API through its own `/api/*` rewrite, so the login cookie belongs to the dashboard's domain and no CORS or cookie-domain setup is needed. Rewrites are resolved at build time, so **redeploy the dashboard if `API_URL` ever changes**.

## 6. Portfolio website on Vercel

The API-connected code is on the `backend-intrigation` branch.

1. Vercel → your portfolio project → **Settings → Environment Variables** (Production and Preview):

   | Variable | Value |
   |---|---|
   | `CONTENT_API_URL` | `<API_URL>/api/v1` |
   | `SITE_SLUG` | `shovon` |
   | `REVALIDATE_SECRET` | the secret from step 3 |

2. Merge `backend-intrigation` into `main` (or open a PR and merge it). Vercel builds and deploys.
   The build prerenders pages from the API, so the Render service must be up. The build allows 180s per page for a cold start. If a build still fails with a fetch error, open `<API_URL>/health` once to wake it, then **Redeploy**.

## 7. Check everything end to end

1. Open `ADMIN_URL`, sign in with the admin from step 3, then change your password under **Account**.
2. **Site settings** → **Revalidate now** → expect "Website refreshed (HTTP 200)". A 401 means `REVALIDATE_SECRET` differs between Vercel and the database. Rotate it there and update Vercel.
3. Change the Hero headline → **Save** → reload the portfolio: it shows the new text.
4. Upload an image to a project (this checks Cloudinary and that the upload passes through the dashboard's proxy), then check it on the portfolio.
5. Send a message from the portfolio's contact form → it appears under **Messages**.
6. Upload a resume PDF under **Profile → Resume** and click the site's **Download Resume**. If Cloudinary blocks it, enable *Settings → Security → Allow delivery of PDF and ZIP files*.

## Later

- **Custom domain for the portfolio:** add it in Vercel, then in the dashboard → Site settings update **Website URL**, **Allowed origins** (add the new origin) and **Revalidate URL**.
- **Custom domain for the dashboard:** update `ADMIN_ORIGIN` on Render.
- **New API URL** (e.g. custom domain on Render): update `BACKEND_URL` (redeploy the dashboard) and `CONTENT_API_URL` (redeploy the portfolio).
- **Logging everyone out:** change `JWT_SECRET` on Render.
- **Backups:** the free Atlas tier has no automated backups. Use `mongodump --uri "<ATLAS_URI>"` occasionally, or upgrade the cluster.
